# 해석 정정 — "사용자가 늘리는 방향" ≠ 월드/화면 고정 축 (HANDLE_ROLE_MEMO 보충)

> **배경**: `HANDLE_ROLE_MEMO.md`(변형 역할 = 로컬 축, R은 R로 유지)에 대해 그쪽 AI가
> *"지금 요청하신 '화면상 사용자가 늘리는 방향으로'는 반대로 월드/화면 고정 축을 요구하는 것 같아 메모의 결론과 정반대"* 라고 회신함.
> **결론: 모순 없음. 오독이다.** "사용자가 당기는 방향" = **회전된 로컬 축**(핸들이 놓인 그 축) 방향이며, 이는 메모의 로컬 축 계약과 **같은 동작**이다. 레퍼런스(map-aabb)에서 회전 상태로 실측해도 R은 R로 동작하면서 동시에 커서를 그대로 따라온다 — 두 성질은 동시에 성립한다.

---

## 1. 왜 같은 것인가 (한 단락 증명)

45° 회전한 사각형에서 R 핸들은 화면상 대각선 위치에 있다. 이때 **R 핸들이 놓인 축**은 도형 로컬 X축이 회전해 화면에 보이는 그 대각선이고, **사용자가 핸들을 당기는 방향**도 바로 그 대각선이다(핸들이 거기 있으니까). 따라서 **포인터 변위를 회전된 로컬 축에 투영**하는 것 = **사용자가 당기는 방향을 따라가는 것**. 하나의 동작에 대한 두 표현일 뿐이다.

---

## 2. 세 가지 해석 구분표 (오독 방지의 핵심)

| 해석 | 45° 회전 + R 핸들 드래그 시 동작 | 판정 |
|---|---|---|
| **① 로컬 축 (메모의 계약 = 요청의 진짜 의미)** | 포인터를 로컬로 역변환 → **로컬 X 성분만** 사용 → 도형이 자기 폭 방향(화면상 대각선 = 당기는 방향)으로 늘어남 | ✅ 정상. 메모의 결론이자 사용자 기대 |
| **② 월드/화면 고정 축 (그쪽 AI가 오해한 해석)** | 화면 가로 이동 → 기울어진 도형을 **화면 가로로** 늘림 → 로컬에서 양축 변화 + **shear(비틀림)** | ❌ **요청된 적 없음.** similarity 모델로는 표현도 안 되는 변형 |
| **③ 역할 오판 (원래 버그)** | R을 RB(corner)로 분류 → 양축 스케일 + 대각 앵커 | ❌ 메모가 지적한 버그 |

> 요청 문구 "화면상 사용자가 늘리는 방향으로"를 ②로 읽으면 메모와 모순처럼 보인다. 진짜 의미는 ①이고, ①은 화면상으로도 사용자가 당기는 방향 그대로 움직인다 — **그 방향 자체가 회전된 로컬 축이기 때문**이다.

---

## 3. 공식 (edge 핸들, 회전 무관하게 동일)

```
p_local = inverse(rotation) · inverse(frame) · pointer      // 포인터를 로컬로 역변환
fx = ((p_local − A) · x̂) / ((h0_local − A) · x̂)             // 로컬 X 성분만 취함 (edge R)
fy = 1                                                        // edge는 다른 축 고정
```
- "로컬 X 성분만 취함" = "화면상 회전된 축 방향으로 투영" — 같은 연산.
- 화면에서 보이는 결과: 핸들이 **커서의 (그 축 위) 투영점을 따라 미끄러짐** — 사용자가 당기는 방향 그대로.

## 4. 레퍼런스(map-aabb) 실측 근거

- `getPointerLocalMeters`가 포인터를 **역회전 포함 로컬 좌표**로 변환하고, 핸들 로직은 그 로컬 값을 그대로 사용.
- 그래서 회전 상태에서도: 화면에서는 핸들이 커서를 따라오고(①의 "당기는 방향"), 로컬에서는 자기 축 기준으로 변형(①의 "R은 R").
- **월드 고정 축(②) 동작은 어디에도 없다** — 그런 코드 경로 자체가 없음. (`HANDLE_ROLE_MEMO.md` 2장의 구조와 동일한 이유)

---

## 5. 그쪽에 돌려줄 최종 회신 (복사용)

> "사용자가 늘리는 방향으로"는 **월드/화면 고정 축 요구가 아니다.**
> 포인터 변위를 **회전된 로컬 축(그 핸들이 놓인 축)에 투영**하라는 뜻이고, 이는 HANDLE_ROLE_MEMO의 로컬 축 계약과 **정확히 같은 동작**이다.
> 회전된 도형을 화면 고정 축으로 늘리면 shear가 생기는데 그것은 요청된 적이 없고, similarity 변형 모델과도 맞지 않는다.
> 따라서 메모의 결론(변형 역할 = 로컬, R 유지)대로 구현하면 "사용자가 당기는 방향" 요구도 자동으로 충족된다. 두 요구는 하나다.

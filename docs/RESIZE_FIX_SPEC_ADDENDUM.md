# 리사이즈 패치 스펙 — 보충 (Addendum: 실측 우선 · 재작성 금지 · frame0 이중 표현 검증)

> `RESIZE_FIX_SPEC.md`(원본 스펙)에 대한 그쪽 프로젝트 검토를 반영한 보충. **원본 스펙의 상위 원칙(불변식·패치 범위·검증)은 그대로 유효**하며, 이 문서는 그 위에 3가지를 추가/정정한다.
>
> 그쪽 검토 요지: ① 상위 원칙은 유지할 가치가 있다. ② 그러나 의사코드를 그대로 구현하는 것은 비권장 — 이미 존재하는 frame freeze 로직·factor 계산을 모르고 재작성하면 중복·회귀 위험이 크다. ③ 실제 스펙에 추가해야 할 4번째 체크포인트는 **경로 A(anchor pixel)와 경로 B(guide frame) 두 frame0 표현이 항상 동일한 값을 내는지 검증 통합**이다. ④ 코드를 건드리기 전에 **이미 있는 로그로 실측 먼저**.

---

## A. 실측 먼저 — 코드 수정 전 필수 선행 (Step 0)

> 코드를 건드리기 전에 **이미 있는 로그로 실측**한다. 진단이 실측과 다르면 수정 지점도 달라진다.

- [ ] bottom 드래그 한 세션 동안 기존 로그로 기록:
  - **경로 A — anchor pixel 표현**의 frame0 값
  - **경로 B — guide frame 표현**의 frame0 값
  - 프레임별 targetFrame 계산의 **실제 입력** (무엇을 읽고 있는지)
- [ ] **A·B 두 표현이 갈라지는 첫 프레임**을 찾는다 → 그 지점이 실제 수정 대상.
- [ ] 드래그 내내 안 갈라지면? → 원인이 다른 곳에 있다는 뜻 — 원본 스펙의 수정 지점 가설을 재검토하고 결과를 공유.
- [ ] applied state가 입력으로 재사용되는 **실제 변수/필드**를 로그로 특정한다. (추정 금지 — 실측으로 지목)

## B. 4번째 체크포인트 — frame0 이중 표현 일치 검증 (원본 스펙 2장에 추가)

- [ ] 드래그 시작 프레임이 **경로 A(anchor pixel)** 와 **경로 B(guide frame)** 두 표현으로 존재한다 — 두 표현이 드래그 **전 구간에서 항상 동일한 값**을 내는지 검증을 통합한다.
- [ ] **두 표현이 갈라지는 순간 = 드리프트 발생 지점.** 따라서 이 검증(assert)은 일회성 확인이 아니라 **상시 회귀 감시 장치**로 남긴다.
- [ ] 원본 스펙 4장 검증 매트릭스에 게이트 추가: *"frame0 이중 표현 일치 — A·B가 드래그 전 구간 동일 값 (실측 로그 → 수정 후 assert 상시화)"*

## C. 의사코드의 지위 정정 — "계약 형상"이지 재작성 지시가 아님 (원본 스펙 3장에 대한 주의)

- [ ] 원본 스펙 3장의 의사코드는 **코드가 만족해야 할 계약의 형상(shape)** 이다. **이대로 새로 구현하지 말 것.**
- [ ] 이미 존재하는 **frame freeze 로직**과 **factor 계산 로직**을 모른 채 재작성하면 **중복 구현 + 회귀** 위험이 크다.
- [ ] 올바른 사용법: 기존 로직을 의사코드 형상에 **대조(audit)** 하여, 계약과 어긋나는 지점만 **최소 수정**한다. 어긋나는 지점은 A장의 실측이 지목한다.

## 적용 순서 (원본 스펙과 합친 최종 워크플로)

1. [ ] **A장 실측** — A·B 표현이 갈라지는 첫 프레임 + 재사용되는 변수 특정
2. [ ] 실측 결과를 원본 스펙 1장(3지점)과 대조 — 실제 수정 지점 확정
3. [ ] 기존 frame freeze·factor 로직을 **audit** — 어긋나는 지점만 최소 수정 (재작성 금지)
4. [ ] **B장 assert 상시화** — frame0 이중 표현 일치 감시
5. [ ] 원본 스펙 4장 매트릭스(3경로 × 실험 1~3) + B장 게이트 검증
6. [ ] 통과 시 `ROTATION_FIX_FINDINGS.md`에 **Finding #3** 기록 (실측 결과 포함)

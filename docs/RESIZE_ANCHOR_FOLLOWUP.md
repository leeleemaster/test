## 2. 종합 진단 (유력 — 확정은 3장 후속으로)

freeform 경로의 설계 자체("시작 상대점을 타깃 프레임으로 매핑")는 유효하다. 문제는 **타깃 프레임을 만드는 재료**다:

```
[올바른 계약]   타깃 프레임 = f( ★드래그 시작 guide 프레임(불변), 현재 포인터, 핸들 종류 )
                anchor(반대변) = 시작 프레임에서 1회 확정, 드래그 내내 불변

[현재로 추정]   타깃 프레임 = f( 변하는 현재 guide 박스, old bounds에서 온 anchor )
                + 답3의 "점→bounds 재계산"이 드래그 중 다음 프레임 박스로 피드백
```

이 구조가 두 신호를 모두 설명한다:
- **4변 수축**: edge에서 `factorX=1`이어도, 매 프레임 **프레임 원점·anchor가 드리프트**하면 매핑 결과가 X쪽으로도 밀리며 오차가 복리로 쌓임. 회전된 그룹이면 "프레임 기반 바운즈 재구성"(답5의 방어)이 매 프레임 재적합되며 **AABB 재적합 수축 루프**가 겹쳐 증폭.
- **위치 이동**: anchor가 old bounds 기준이라 "고정이어야 할 반대변"이 프레임마다 이동.

> 이것은 회전 버그의 "delta 누적" 원칙 위반과 **동형**이다: 기준(스냅샷)이 아니라 **변하는 자기 자신**을 참조하며 증분 적용 → 누적 오차. 해법도 동형: **스냅샷 기준 절대 계산**.

## 3. 후속 요청 (그쪽 AI에 복사해서 전달)

아래에 각 1~2줄, 가능하면 코드 한 줄로 답해줘. (목적: "가이드 박스 비고정 + old bounds anchor"가 1차 원인인지 확정)

1. **왕복(jiggle) 테스트 결과**: bottom을 아래→위→아래로 드래그해 포인터를 시작점에 되돌렸을 때, 도형이 원래 크기·위치로 돌아오나? (안 돌아오면 스냅샷 위반 확정)
2. **타깃 가이드 프레임 계산 코드**: 그 함수의 **입력**이 (드래그 시작 프레임 + 포인터)인가, (현재 박스 + old anchor)인가? 해당 코드 붙여줘.
3. **anchor data 갱신 시점**: 드래그 시작에 1회 확정인가, 매 프레임(또는 매 이벤트) old bounds에서 다시 읽나?
4. **bounds 재계산 피드백**: 답3의 "점→경계 재계산" 결과가 **드래그 중** 다음 프레임의 guide 박스 계산에 들어가나, 아니면 **commit(pointer-up)에만** 반영되나?
5. **경로 분리 확인**: 증상이 **그룹 freeform 경로에서만** 나고, local(반대변 피벗) 리사이즈는 정상인가? (정상이면 진단 확정에 큰 근거)
6. **회전 의존성**: 회전 0°와 45°에서 증상의 크기가 같은가, 45°에서 더 심한가? (더 심하면 AABB 재적합 루프가 증폭자로 겹친 것)
7. **rotate 영향 범위**: 공유하는 multi figure guide session의 guide 박스가 드래그 중 갱신된다면, **rotate 드래그 중에도** 같은 박스를 읽는 코드가 있나? (있다면 회전에도 잠재 영향)

## 4. 확정 시 수정 방향 (미리 합의용 — 적용은 확정 후)

- [ ] **스냅샷 계약 도입**: 드래그 시작 시 `startGuideFrame`(박스+anchor)을 1회 확정하고 **드래그 내내 불변**. 타깃 프레임은 항상 `f(startGuideFrame, 현재 포인터, 핸들)`로 계산 — 매 프레임 독립(idempotent) → 왕복 시 원위치 복귀 보장.
- [ ] **anchor 명시화**: freeform 경로에도 "반대변 고정"을 타깃 프레임 구성에서 **명시적으로** 박는다 (암묵 앵커 금지). 시작 프레임의 반대변 좌표를 그대로 타깃 프레임에 복사.
- [ ] **bounds 재계산은 commit에만**: 드래그 중 "점→경계 재계산"이 guide 박스로 피드백되지 않게 차단. pointer-up에서만 박스 갱신.
- [ ] 매핑 입력은 (이미 고정인) figure start state + startGuideFrame — 현재 상태를 입력으로 쓰지 않는다.
- [ ] **검증**: `RESIZE_ANCHOR_ANALYSIS.md` 실험 1(0° bottom: top·left·right 불변) + 실험 2(왕복 복귀) + 실험 3(45°에서도 동일) 통과. 저장 라운드트립(commit 값 의미가 바뀌지 않는지)도 확인.

> 원칙 재확인: 회전을 "절대각 set"으로 고친 것과 같은 원칙 — **변하는 자신을 참조한 증분이 아니라, 불변 스냅샷 기준의 절대 계산**. 이 프로젝트에서 세 번째로 확인되는 같은 계열이다 (회전 delta 누적 → 커밋 이중 반전 → 리사이즈 비고정 프레임).

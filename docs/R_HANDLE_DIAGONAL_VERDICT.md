# R 핸들 "대각선으로 늘어남" — 정상/버그 판정 기준 (+ 레퍼런스의 무움찔 수정)

> **배경**: 오른쪽(시계방향)으로 회전한 도형에서 그쪽 프로젝트가 *"실측 결과 role=R이고 대각선으로 늘어나는 게 정상"* 이라고 주장.
> **이 문서의 결론**: **"대각선으로 늘어남"은 정상의 증거가 아니다.** `HANDLE_AXIS_CLARIFICATION.md`의 45° 예시를 "대각선=무조건 정상"으로 일반화하면 오용이다 — 대각선이 정상인 건 **회전각이 그만큼일 때만**이다. 아래 4조건 + 작은 각 테스트로 판정한다.

---

## 1. 정상 판정 4조건 (동시에 성립해야 정상)

| # | 조건 | 실측 방법 |
|---|---|---|
| 1 | **늘어나는 방향각 = 도형 회전각** — 정확히, 그리고 **연속적으로** 일치 | 핸들 궤적의 화면 각도를 재서 `groupRotation`과 비교 |
| 2 | **무왜곡** — 회전된 직사각형이 그대로 유지 (shear 없음, 코너 90°) | 드래그 중 스크린샷에서 코너각 확인 |
| 3 | **반대변(로컬 L) 화면 픽셀 고정** | 드래그 중 L변 중점 화면 좌표 로그 (`assert(currentAnchorPx ≈ startAnchorPx)`) |
| 4 | **로컬 높이 불변** (fy = 1, 폭만 변화) | 로컬 Y extent 로그 |

> "role=R로 찍혔고 대각선으로 늘어난다"는 **조건 1의 절반**만 본 것이다. 나머지를 재지 않으면 버그가 그 뒤에 숨는다.
> (참고: `GROUP_RESIZE_SCREENSPACE_FIX.md` §5 — "픽셀 크기 로그로 문제없음 오판"과 같은 함정. **무엇을 측정하는가가 판정을 가른다.**)

## 2. 결정적 판별 — 작은 각 테스트

> **도형을 10~15°만 오른쪽으로 회전시키고 R을 드래그하라.**
- **정상**: 거의 수평에 가까운, **딱 10~15° 기울어진** 방향으로만 늘어남
- **버그**: 여전히 45° 근처의 뚜렷한 대각선 → role 로그가 R이어도 실제 변형은 다른 짓을 하는 것 (corner성 양축 변형, 축 계산 오류 등)

**대각선이 정상인 것은 회전각이 그만큼일 때만이다.** 회전각과 무관하게 항상 비슷한 대각선이면 100% 버그.

## 3. 그쪽에 요구할 실측 (role 로그 말고 이 3개를 수치로)

- [ ] ① 늘어난 방향각 vs 회전각 (여러 회전각에서: 10°, 30°, 45°, 70°)
- [ ] ③ 반대변 화면 좌표 — 드래그 시작 대비 픽셀 이동량
- [ ] ④ 로컬 높이 — 드래그 전/후 값

### 돌려줄 회신 (복사용)
> "대각선으로 늘어남"은 정상의 증거가 아니다. 정상의 정의는 **"늘어나는 방향각 == 회전각, 반대변 화면 고정, 로컬 높이 불변, 무왜곡"** 4가지다.
> 특히 **작은 회전각(10°)에서 늘어나는 방향도 10°인지** 보여달라. 45°가 아닌 각도에서도 대각선이면 버그다.
> role=R 로그는 판정에 불충분하다 — 크기/role처럼 버그가 안 건드리는 변수 말고, 방향각·앵커 위치·로컬 높이를 재라.

## 4. 비교 기준: 레퍼런스(map-aabb shape-tester)의 정상 동작 + "움찔거림" 수정

그쪽 실측과 나란히 비교할 기준. 우리 shape-tester는 위 4조건을 만족하며, **회전·리사이즈 중 다른 점들이 움찔거리던(핸들 점프) 현상도 수정**되어 있다.

### 움찔거림의 원인과 수정 (커밋 `54d965d`, 상세: `GROUP_RESIZE_SCREENSPACE_FIX.md` §6)

**증상이었던 것**: 그룹을 회전시키면 핸들·점들이 요동(점프)치고, 스케일하면 자식이 박스 밖으로 삐져나옴.

**원인**: 그룹 박스를 매 프레임 자식들의 **화면 AABB로 재계산** → 회전 시 자식이 호를 그리며 움직여 AABB 모양·크기가 매 프레임 바뀜 → 핸들 위치 요동. (= "변하는 자신을 참조" 계열 — 회전 delta 누적, 리사이즈 applied-state 재사용과 같은 뿌리)

**수정 — "지속 회전각 + tight 도출 박스" 모델**:
```
지속 상태: groupRotation 하나뿐 (선택 SET 변경 시 0 리셋)
매 렌더:   각 자식 정점을 −groupRotation으로 돌린 그룹 로컬축에서 AABB 도출
```
- **회전 시**: 자식과 프레임이 같은 각도로 돌므로 그룹 로컬에서 자식이 **안 움직임** → AABB 불변 → 박스가 **강체로 회전 = 핸들·점 안 움찔**
- **스케일 시**: 박스가 매 렌더 자식을 tight하게 감쌈 = 안 삐져나옴. 앵커·스케일 인자는 여전히 **드래그 시작 스냅샷** 고정 (출력→입력 피드백 없음)
- 구현: `shape-tester.tsx`의 `computeGroupBox(sel, rotationDeg)` + `group-scale`의 `anchorLocal` 스냅샷 `P' = A + S·(P₀ − A)`

### 이게 판정과 연결되는 이유
- 레퍼런스에서 θ° 회전 후 R 드래그하면: **정확히 θ° 방향으로만** 늘어나고, 반대 모서리는 고정되며, 다른 점들은 비례 이동 외에 어떤 요동도 없다. **이것이 "정상"의 기준 형상**이다.
- 그쪽의 "대각선으로 늘어나는 게 정상" 주장은 **같은 회전각에서 레퍼런스와 나란히 실행**해 방향각·앵커·요동 여부를 비교하면 즉시 판정된다.
- 만약 그쪽에서 R 드래그 중 **다른 점들이 미세하게 움찔거린다면**, 그것 자체가 "매 프레임 재도출/피드백" 구조의 증거 — 위 수정 모델(지속 상태 최소화 + 스냅샷 절대 계산)을 적용해야 한다.
